2. Архитектура диалоговой системы

Любая серьёзная система строится из слоёв:

A. Data-слой (скрипт диалога)
Формат: YAML / JSON / CSV или собственный node-graph (Unity Yarn Spinner, Ink, Ren'Py, либо кастом HoYoverse). Сущности: SpeakerLineChoiceConditionBranchCameraCueEmoteVoiceClipSubtitleLocalizedText. Диалог должен быть data-driven, отделён от кода. HSR хранит сцены как граф с узлами — это даёт ветвление и переиспользование.
B. Локализация (i18n pipeline)
Минимум 13 языков у HoYoverse. Текст → таблицы → TM (translation memory) → QC. Проблема: длина строк (нем./рус. длиннее китайского в 2–3 раза) → адаптивный UI (auto-fit, wrap, dynamic box). Voice lip-sync: озвучка пишется под оригинал (CN/JP), субтитры локализуются отдельно → рассинхрон (типично для WuWa/Genshin). Решение HoYoverse — «soft subtitle timing».
C. Presentation-слой (UI/HUD)
Dialogue box, nameplate, avatar/portrait, expression sprites. Speed lines, типографика, кинематографичные рамки (HSR — стиль «комикс», ZZZ — неон/glitch). Слой камеры: диалог управляет камерой (CameraCue) — зум, focus на говорящем, depth-of-field.
D. Audio / VO-слой
Streaming VO по фразам, привязка к subtitle timing. Выбор языка озвучки независимо от текста. «Auto» / «Skip» / «History» — стандарт VN-функций.
E. Interaction-слой
Выборы (branches), радиальное меню (ZZZ), QTE-вставки, мини-игры (телефон HSR, «Video Play»). Системы «Trust / Companionship», влияющие на доступные реплики.

3. Сравнительный разбор механик

Honkai: Star Rail — эталон «геймифицированного» диалога

  • Ветвление с возвратом: выборы ведут к разным репликам, но сходятся к одной сюжетной точке (illusion of agency). Дешевле настоящих концовок.
  • Система «Телефон»: чаты, звонки, соцсеть «Interastral Peace», мини-игры — диалог живёт вне катсцен.
  • Выражения и позы: портреты меняются (happy / serious / shocked) → эмоциональность без full motion.
  • Companion quests и guest conversations: рост отношений через повторяющиеся диалоги.
  • Динамический бокс: адаптация под длину текста + иконки предметов/персонажей внутри текста (rich text).

Zenless Zone Zero — скорость и стиль

  • Радиальное/быстрое меню выбора: реплики появляются как пузыри, выбор мгновенный, pacing быстрее HSR.
  • «Vibe» диалог: короткие реплики, сленг, break-the-fourth-wall (обращение к игроку как к «Proxy»).
  • Меньше длинных монологов, больше banter — снижает усталость от чтения.

Wuthering Waves — фокус на озвучку и скип

  • Полный дубляж на 4 языках с самого релиза (исправили провал 1.0).
  • Агрессивный skip и auto-play — уважение ко времени игрока.
  • Диалог в мире (NPC overhead bubbles) + VN для стори.

Reverse: 1999 / Limbus Company — нарративный упор

  • Reverse: 1999 — стилизация под 1920-е, диалог как литература, богатый текст.
  • Limbus Company — текстовые логи, выборы с моральными последствиями, интеграция с боёвкой через «указания».

Arknights — модульная подача

  • Story modules, операторские записи, Side Stories. Диалог часто в «окне оператора» + катсцены.
  • Глубокий лор через кодекс и неявные связи.

4. Связанные системы (что окружает диалог)

Character / Affinity
Уровни привязанности (HSR «Companionship», Genshin «Hangout Events» с ветвящимися концовками, WuWa квесты). Диалог — главный канал прокачки отношений.
Quest / Story
Диалог привязан к квестам через триггеры и флаги состояния (state machine сюжета).
Codex / Lore
Собранные диалоги, записи, архивы (Arknights, HSR «Data Bank»).
Event system
Временные диалоги, часто легче и юморнее основного сюжета.
Photo / Interaction
Nikke (комната, селфи), Genshin (питомцы) — физическое взаимодействие как продолжение диалога.
System / Settings
Скорость текста, язык VO, субтитры, auto/skip/history — часть UX диалога.

5. Ключевые паттерны и метрики успеха

  • Illusion of choice — ветвление, сходящееся к канону (экономия бюджета при ощущении агентства).
  • Pacing — чередование VN ↔ экшен, чтобы не утомлять. ZZZ/HSR — лучшие.
  • Character voice consistency — у каждого персонажа «речевой паттерн» (ZZZ использует сленг / break-4th-wall).
  • Accessibility — скип, история, скорость, размер шрифта.
  • Replayability диалога — архивы и повторные беседы (HSR guest convos).
  • Качество локализации > количество языков. Плохой перевод убивает погружение сильнее, чем отсутствие VO.

6. Чек-лист для своей системы

  • Data-driven граф диалога (Ink / Yarn / кастом) с узлами line / choice / condition / camera.
  • i18n из коробки: единый источник строк + адаптивный UI под длину.
  • VO streaming с независимым выбором языка + soft subtitle timing.
  • Ветвление с возвратом + система флагов/состояний сюжета.
  • Внесценический диалог: чат / телефон / соцсеть для «живого» мира.
  • Affinity-layer, связанный с уникальными репликами и концовками (hangout-style).
  • UX-триада: Auto / Skip / History + настраиваемая скорость и шрифт.
  • Camera cues в диалоге для кинематографичности без full motion video.
  • Архив / кодекс всех пройденных диалогов.
  • QC-пайплайн: lip-sync check, overflow check, translation memory.

    9. Примеры диалоговых ситуаций из практики

    Конкретные кейсы, которые иллюстрируют, как работают системы в реальных играх:

    Ситуация A — «Иллюзия выбора» (HSR, выбор реплики персонажу)

    Игрок выбирает тон ответа NPC: дружелюбный / нейтральный / саркастичный. Каждая ветка даёт уникальную реплику-реакцию, но через 2–3 шага сюжет сходится к одной и той же точке. Это создаёт ощущение влияния без необходимости писать 3 полноценные концовки.

    branchconvergereuse

    Ситуация B — Внесценический чат (HSR «Телефон»)

    Персонаж пишет в «Interastral Peace» между миссиями. Диалог не блокирует геймплей — это асинхронное сообщение. Решается через очередь событий (event queue) + отдельный UI-слой поверх мира. Важно: такие реплики не должны нести критичный для сюжета контент, иначе игрок пропустит его.

    asyncoverlay UInon-blocking

    Ситуация C — Радиальное меню (ZZZ)

    Вместо списка вариантов снизу — пузыри реплик вокруг портрета, выбор мгновенный. Это меняет архитектуру: выборы должны рендериться в координатах экрана (world/UI space), а не в фиксированном боксе. Pacing ускоряется, но теряется «чтение» — подходит для казуального банаterа, не для драмы.

    radial menupacingscreen-space

    Ситуация D — Hangout Events (Genshin)

    Мини-квест с деревом решений и несколькими концовками для одного персонажа. Здесь ветвление НАСТОЯЩЕЕ: выбор меняет финал, а прогресс сохраняется в отдельный state (не в глобальный сюжет). Проблема: нужна отдельная система «пройденных веток», чтобы игрок мог добрать остальные концовки.

    true branchmultiple endingsseparate state

    Ситуация E — Моральная дилемма (Limbus Company)

    Выбор «указания» в бою и диалоге влияет на отношение команды и доступный текст позже. Здесь диалог связан с боевым state machine — реплики зависят от переменных (relations, sanity). Требует единого контекста данных между боём и диалогом.

    state-drivencross-systemvariables

    Ситуация F — Локализация длины (Genshin / WuWa)

    Китайская фраза в 10 иероглифов на русском превращается в 3 строки. Если бокс фиксированный — текст обрезается или вылезает. Решение: динамическая высота бокса + auto-wrap + минимальный/максимальный padding, плюс лимиты символов при написании оригинала.

    i18nauto-fitoverflow

    10. Проблемы, которые приходится решать при создании

    1. Lip-sync рассинхрон
    VO пишется под оригинал (CN/JP), локализованные субтитры длиннее. Фраза кончается, а текст ещё читают. Решение: soft timing, паузы, «grace period».
    2. State spaghetti
    Флаги сюжета растут, ветки пересекаются. Баг: «персонаж здоровается как в первый раз» на 20-м часе. Решение: явный quest state machine, версионирование сюжета.
    3. Непереиспользуемость контента
    Каждая сцена пишется руками. Решение: шаблоны реплик, теги переменных ({player_name}, {item}), data-driven подход.
    4. Производительность VO
    Тысячи аудиофайлов. Грузить все нельзя. Решение: streaming по фразам, префетч следующей реплики, кэш коротких SFX.
    5. Скип и целостность
    Игрок скипает диалог — теряет контекст и потом не понимает квест. Решение: архив/кодекс, краткое резюме пропущенного, обязательные «якорные» строки без скипа.
    6. Доступность
    Дислексия, слабое зрение, глухота. Решение: размер шрифта, контраст, субтитры обязательны при VO, TTS-хук.
    7. Контент-пайплайн
    Сценаристы пишут в Excel/Google Docs, инженеры ждут JSON. Решение: единый редактор (Ink/Yarn/кастом tool), авто-экспорт, preview в редакторе.
    8. Ветвление и бюджет
    Каждая ветка = запись VO + локализация × 13 языков. Решение: converge-паттерн, озвучка только ключевых веток, остальное текстом.

    11. Практики и решения (how-to)

    • Единый формат данных: описывай диалог как граф узлов, а не список строк. Узел = {id, speaker, text, choices[], next[], conditions[], camera, vo}.
    • Разделяй контент и код: сценаристы не должны трогать движок. Давайте им визуальный редактор с live-preview.
    • Переменные в тексте: используйте токены ({name}, {gender}, {item_icon}) — один скрипт на все локали и пол персонажа.
    • Converge-ветвление: давайте 2–4 уникальные реплики реакции, но возвращайте к общему стволу — экономия VO/локали.
    • Якорные строки: помечайте критичные реплики флагом no-skip, чтобы сюжет не терялся при скипе.
    • Адаптивный бокс: auto-height + max-lines + scroll для переполнения; лимиты символов при написании.
    • VO streaming + preload: грузите следующую фразу заранее, кэшируйте; soft subtitle timing под локаль.
    • State machine сюжета: храните прогресс как явные состояния, версионируйте при патчах, избегайте хаоса флагов.
    • Архив/кодекс: сохраняйте пройденные диалоги для повторного чтения и для тех, кто скипнул.
    • QC-автоматизация: боты проверяют overflow, пустые поля локали, отсутствие VO, битые теги — до релиза.
    • Accessibility по умолчанию: настраиваемый шрифт/скорость/контраст и обязательные субтитры при озвучке.
    • Телеметрия: метрики skip-rate и time-on-dialog подсказывают, где диалог затянут или скучен.
